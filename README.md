# お先にどうぞ？ — Robot Intent Coordination

ROS 2 HumbleとIgnition Gazeboを使用した、2台のCRANE+ V2ロボットアームによる協調動作の実験プロジェクトです。

## 概要

2台のロボットが共有作業空間でPICK動作を試みる状況を想定し、相手の動作意図を推定しながら、作業順序を調整するシステムを構築しました。

各ロボットはランダムなタイミングでPICKを要求します。相手のPICK意図をRandom Forestで推定し、必要に応じてROS 2 Serviceで相手の状態を確認します。共有作業空間の排他制御によって、2台のロボットが同時に作業することを防ぎます。

## 主な機能

- **2台の独立制御：** ROS 2の名前空間を分離してCRANE+ V2を制御
- **意図推定：** Random ForestによるPICK／NON-PICK分類
- **対話：** ROS 2 Serviceによる相手ロボットの状態確認
- **協調動作：** 共有領域の使用権を調停し、PICKとYIELDを実行
- **シミュレーション：** Ignition Gazebo上で協調動作を可視化

## システム構成

各ロボットの関節角度4個と、約0.3秒間の角度変化量4個を特徴量として使用します。

1. ロボットA・BがランダムなタイミングでPICKを要求
2. 相手の関節状態をRandom Forestで分類
3. 推定スコアが閾値を超えた場合、ROS 2 Serviceで相手の作業状態を確認
4. 中央の調停機構で共有作業空間の使用権を取得
5. 使用権を取得したロボットがPICK動作を実行
6. 作業終了後、待機中のロボットに使用権を引き渡す

## 実行環境

- ROS 2 Humble
- Ignition Gazebo
- Python 3
- scikit-learn / pandas / NumPy
- CRANE+ V2 ROS 2関連パッケージ
- ign_ros2_control

## 実行方法

必要なROS 2パッケージとシミュレーション環境を構築した後、Gazeboを起動します。

```bash
ros2 launch ./dual_crane.launch.py
```

コントローラーが起動したことを確認し、別のターミナルで以下を実行します。

```bash
python3 dual_pick_ai_final.py
```

Gazeboのシミュレーションを再生状態にしてください。

※ 本プロジェクトのlaunchファイルには、実験環境の絶対パスが含まれています。別の環境で実行する場合はパスの調整が必要です。

## 実験結果

2台のロボットがランダムにPICKを要求する状況で、Random Forestによる意図推定、ROS 2 Serviceによる状態確認、および共有領域の排他制御を組み合わせた協調動作を確認しました。

一方のロボットがPICK動作中、もう一方はYIELDして待機し、作業終了後にPICKを開始します。

## 制約と今後の課題

- 意図推定モデルは少数の実験データで学習しており、分類精度の独立した検証は未実施
- AIはService確認のきっかけとして利用し、作業順序の最終決定は調停機構が担当
- 実際の物体把持ではなく、PICKを模した動作を実装
- 現在の排他制御は単一Pythonプロセス内で実施
- より多様な学習データ、実機での検証、分散環境での協調制御が今後の課題

## 実行環境に関する注意事項

本プロジェクトは、ROS 2 HumbleとIgnition GazeboをインストールしたDocker環境で開発・動作確認しました。

以下のファイルには、開発環境固有の絶対パスが含まれています。

- `dual_crane.launch.py`：URDF、SDF、コントローラー設定ファイルなどの参照先
- `dual_pick_ai_final.py`：学習済みモデル `/workspace/intent_model.pkl` の参照先

また、実行にはCRANE+ V2のROS 2関連パッケージ、`ign_ros2_control`、必要なメッシュファイルなどが別途必要です。

そのため、**GitHubからcloneするだけでは直ちに実行できません。** 利用環境に合わせてパスや依存パッケージを設定する必要があります。
